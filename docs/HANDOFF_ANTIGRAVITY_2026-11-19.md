## 4. ตัวปรับคำ `fixHeard` — `lib/heard-fix.ts:460`

ทำงานแบบกฎตายตัว ไม่เรียก LLM (ไม่กิน token) เฉลี่ยราว 0.8 ms ต่อประโยค ลำดับขั้น:

1. ยุบประโยคที่ถูกเขียนซ้ำสองรอบ — `collapseRepeat` (`:159`)
2. หน่วยหลังตัวเลข `รัง → ลัง` — `UNIT_HEARD` (`:167`)
3. ข้อความที่ระบบเข้าใจอยู่แล้ว (คำสั่งจอ / สั่งตามเบอร์ / งบ) คืนตามที่ฟังได้ — `isDecision` (`:128`)
4. คำสั่งจอ: เทียบด้วยกุญแจเสียง (`soundKey` `:62`, ตัดวรรณยุกต์ทิ้ง) กับ `COMMAND_WORDS` (`lib/voice-commands.ts:107`) และตารางคำที่ฟังเพี้ยนจนกุญแจเสียงเชื่อมไม่ถึง `COMMAND_HEARD` (`:190`, ตอนนี้มี `หอยกลับ→ถอยกลับ`, `บิว→บิล`) เก็บผลเฉพาะเมื่อปรับแล้วกลายเป็นคำสั่งจริง — `fixCommandWords` (`:195`)
5. คำในแคตตาล็อก — `snapToCatalog` (`:311`) / `snapRun` (`:314`) แล้วต่อด้วยชื่อแบรนด์ภาษาอังกฤษ — `snapLatinBrands` (`:437`)

คลังคำ (`buildHeardVocab` `:234`) สร้างจากสมองสินค้าจริงเท่านั้น: แบรนด์ (น้ำหนัก `BRAND_WEIGHT = 5` `:230`), คำไทยในชื่อสินค้า, คู่ "สองคำแรกของชื่อ", และ "น้องตี๋" · กุญแจเสียงสั้นกว่า `MIN_KEY = 4` (`:229`) ไม่ใช้ · cache ต่อการโหลดสมองที่ `heardVocab()` (`lib/vault.ts:1316`)

ตัวกันคำไทยทั่วไป (`isDictWord` `:289`, `heardRight` `:386`) ใช้ `Intl.Segmenter("th")` ของ Node เอง ไม่มีรายการคำให้ดูแล:

- คำนับเป็น "คำในพจนานุกรม" เมื่อยังเป็นก้อนเดียวในกรอบ `ดี` + คำ + `ดี`
- การแทนคำไม่ตัดผ่ากลางคำในพจนานุกรม และ `ๆ` `฿` เครื่องหมายวรรคตอนเป็นกำแพง
- ช่วงที่เป็นคำในพจนานุกรมล้วนจะไม่ถูกแตะ ยกเว้น 2 กรณี: (ก) เป้าหมายขึ้นต้นด้วยแบรนด์ และช่วงนั้นมีคำในพจนานุกรม 2 คำขึ้นไป (`เท่า แก่ น้อย → เถ้าแก่น้อย`) (ข) เป้าหมายเป็นคำเดียวที่อยู่ในสินค้า ≥ `MIN_COMMON = 5` รายการ (`:308`) และช่วงนั้นมีคำในพจนานุกรม 3 คำขึ้นไป (`แปลง สี ฟัน → แปรงสีฟัน`)

หน่วยนับตามเสียง: `resolveSpokenUnit` (`lib/nong-tee.ts:126`, ใช้ `startsWithUnitSound` ที่ `:138` และ `:140`) เทียบเฉพาะหน่วยที่สินค้าตัวนั้นมีราคาจริงกับหน่วยตั้งต้นของมัน

Test ของตัวปรับคำอยู่ใน `scripts/selftest.ts:287` (รันด้วย `npm test`)

### ตั้งใจให้เป็นแบบนี้ — อย่าแก้กลับ

- ปรับเฉพาะเสียงท่อนสุดท้าย ไม่ปรับข้อความที่ลูกค้าพิมพ์ และไม่ปรับคำบรรยายสด
- `correctHeard` ครอบ try/catch: ตัวปรับคำพังต้องไม่ทำให้คำพูดลูกค้าหาย (`app/api/voice/stt/route.ts:9`)
- ทั้งประโยคที่เสียงเหมือนคำสั่งจะกลายเป็นคำสั่งนั้น (`ปิดใหม่ → ปิดไมค์`, `น่ารัก → หน้าหลัก`) — ยอมรับแล้ว
- คำที่ออกเสียงได้แต่ไม่มีความหมาย (`กร่`, `เรือก`, `ซุกี้`) ผ่านเกณฑ์ "คำในพจนานุกรม" ได้ จึงถูกปล่อยตามที่ฟังได้ ไม่ใช่บั๊ก เป็นขีดจำกัดของวิธีนี้

3. ล็อกโมเดลสนทนา `deepseek-flash` + โหมดประหยัด token — ห้ามเปลี่ยน `LOCKED_FLASH_MODEL` (`lib/nong-tee.ts`) ห้ามเพิ่ม LLM เข้าเส้นทางฟังเสียง
4. ห้ามมีชื่อห้าง/แพลตฟอร์มภายนอกในโค้ด หน้าจอ และเอกสาร · รูปสินค้าผ่าน `/api/img/[token]` · ข้อความผ่าน `sanitizeRetailerText()`
5. ข้อมูลสินค้าห้ามเดา — คลังคำของตัวปรับคำต้องมาจากสมองสินค้าจริงเท่านั้น
6. เงินใช้ `Decimal.js` (`ROUND_HALF_UP`) · ห้ามมีความลับใน git/แชท/log · `npm run scan` ก่อน commit/push ทุกครั้ง
7. commit / push เมื่อลุงจืดสั่งเท่านั้น · ห้าม `git pull` / `reset --hard origin` / force-push

## 8. คำสั่งตรวจ และกับดักที่เจอมาแล้ว

```powershell
npm run scan        # สแกนความลับ
npm run typecheck   # ต้อง 0 error
npm test            # selftest (มีชุดตัวปรับคำ)
npm run uat         # UAT 6 หมวด (ตั้ง $env:UAT_BASE_URL เพื่อยิงเว็บจริง; ค่าตั้งต้น http://127.0.0.1:3090)
```

- **อย่ารัน `npm run dev`** — script ตั้งพอร์ต 3090 ซึ่งเป็นพอร์ตของเว็บจริง ใช้ `npx next dev -p 3190` แทน
- dev server ใช้ `.data/` ร่วมกับเว็บจริง · `npm test` และ `npm run uat` เพิ่มคำสั่งซื้อทดสอบลง `.data/orders.jsonl` ครั้งละ 1 รายการ ไฟล์นี้เพิ่มได้อย่างเดียว ห้ามลบ
- ประโยคไทยอย่าพิมพ์ตรงใน command line (ตัวอักษรเพี้ยน) ให้ใส่ในไฟล์ UTF-8 แล้วให้ Node อ่าน
- สคริปต์นอก Next ที่ import `lib/*.ts` ต้องมีตัว resolve นามสกุล `.ts` แบบที่ `scripts/heard-bench.mjs` และ `scripts/selftest.ts` ใช้ (`registerHooks`)
- ไฟล์ทดลองชั่วคราวใส่ `.data/tmp` (ไม่เข้า git) แล้วลบเมื่อเสร็จ
